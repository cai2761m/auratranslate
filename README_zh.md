# AuraTranslate

## 关于

一个 Chrome 扩展（Manifest V3），为 YouTube 和 Google Drive 视频提供 **AI 驱动的中英双语字幕**。它自动获取 YouTube 英文字幕轨道或 Google Drive 视频转写稿，将碎片化的字幕片段智能合并为自然的完整句子，通过可配置的 LLM API 翻译为中文（简体或繁体），并在视频播放器上直接渲染 **中英双语字幕叠加层**，同时隐藏原生字幕窗口。

无需音频识别，扩展完全基于视频已有的 YouTube 字幕或 Google Drive 转写数据工作。

## 功能特性

- **LLM 智能断句** —— 默认在翻译前用当前实时字幕模型重组跨 cue 的完整句子，避免 `If n / doubles`、`following your / nose` 这类上下句断裂；可在设置中关闭并回退到本地合并。
- **AI 翻译** —— 使用 LLM API 进行上下文感知的字幕翻译，输出自然、高质量的结果。
- **优先级调度** —— 优先翻译当前播放位置附近的字幕，然后在后台继续翻译视频其余部分。
- **ASR 纠错** —— 可选启用 AI 纠正自动生成字幕中的常见语音识别错误。
- **专业术语原文** —— 可选择是否在字幕译文中的专业术语后显示原文，例如 `翻译 (Translation)`；默认开启。
- **可拖拽叠加层** —— 双语字幕叠加层支持直接拖拽重新定位，位置会被持久化保存；Google Drive 的透明播放器遮罩也已适配。
- **可调节字体大小** —— 字幕大小可在设置页面中调整，范围为 0.7× 到 1.8×。
- **稳定翻译缓存** —— 在 `chrome.storage.local` 中缓存已翻译的字幕，并使用稳定的视频/字幕轨道指纹；刷新同一个视频时会复用已有翻译，避免重复调用 API。
- **处理中请求去重** —— 如果翻译尚未完成时刷新页面，同一个字幕 cue 的重复请求会尽量复用后台已有请求，减少重复消耗 token。
- **并行批量翻译** —— 支持同时发送多个翻译批次，按服务商使用不同批量/并发参数，并具备速率限制、坏 JSON、漏返回单条字幕、服务器错误等场景的退避和重试机制。
- **多翻译服务商支持**：
  - **DeepSeek**（默认）—— 只需 API Key 即可开箱即用。
  - **Gemini** —— Google Gemini API，具备专用的批处理参数。
  - **自定义 OpenAI 兼容 API** —— 任何实现了 OpenAI Chat Completions 接口的服务商，包括 API 中转站 / 模型号池服务。

## 安装

1. 打开 `chrome://extensions`。
2. 开启 **开发者模式**。
3. 点击 **"加载已解压的扩展程序"**。
4. 选择下载或克隆的项目文件夹。
5. 点击扩展图标打开设置页面，配置翻译 API。

## 使用方法

1. 打开任意带有英文字幕的 YouTube 视频，或带有转写内容的 Google Drive 视频。
2. 扩展会自动检测 YouTube 字幕轨道；在 Google Drive 中会短暂打开转写面板读取带时间戳的字幕，然后恢复面板。
3. 双语字幕会随着翻译完成实时显示在视频上。
4. 如果未找到英文字幕轨道或 Drive 转写内容，会显示“未找到”状态。

## 配置说明

打开扩展的设置页面（点击扩展图标 → 设置）进行配置：

| 设置项 | 说明 |
|---|---|
| **翻译服务** | DeepSeek / Gemini / 自定义 OpenAI 兼容 API |
| **API Key** | 所选服务商的 API 密钥 |
| **Base URL** | API 端点地址（DeepSeek 和 Gemini 会自动填充） |
| **模型** | 模型名称（DeepSeek 和 Gemini 会自动填充） |
| **JSON 输出模式** | 请求结构化 JSON 输出（如果服务商不支持可关闭） |
| **LLM 智能断句** | 翻译前用 LLM 合并跨字幕的完整句子，默认开启 |
| **ASR 纠错** | 开关 AI 语音识别纠错功能 |
| **专业术语原文** | 控制是否在字幕专业术语后追加原文，默认开启 |
| **源语言** | 英语 |
| **目标语言** | 简体中文 / 繁体中文 |
| **字幕大小** | 字幕缩放倍数（0.7× – 1.8×） |
| **启用字幕** | 开关叠加层显示，同时隐藏 YouTube 原生 CC 字幕 |

### 自定义 OpenAI 兼容 API

如果使用 OpenAI 兼容的 API 中转站，在设置页选择 **自定义 OpenAI 兼容 API**，然后填写：

| 字段 | 示例 |
|---|---|
| **API Key** | `sk-...` |
| **Base URL** | `https://anpin.ai/v1` |
| **模型** | `gpt-5.4` |

建议先保持 **JSON 输出模式** 开启。如果某个服务商不支持 OpenAI JSON mode，可以关闭该选项；扩展仍会尝试解析并恢复可用的翻译结果。

### 缓存行为

扩展会缓存 LLM 断句结果，并按视频、源字幕轨道身份、服务商、接口地址、模型、源语言、目标语言、LLM 智能断句开关、ASR 纠错开关、专业术语原文开关、字幕合并版本和缓存版本来缓存翻译结果。刷新同一个 YouTube 视频时会复用相同配置下的断句和翻译缓存。以下情况才会重新调用 API：

- 该字幕 cue 从未成功翻译过；
- 修改了模型、服务商、Base URL、目标语言、源语言、LLM 智能断句、ASR 纠错或专业术语原文开关；
- 手动清空了本地翻译缓存；
- 字幕合并算法版本发生变化。

## 项目结构

```
├── manifest.json          # Chrome MV3 扩展清单
├── src/
│   ├── background.js      # Service Worker：处理 API 调用和消息路由
│   ├── content.js         # Content Script：字幕获取、翻译队列、叠加层渲染
│   ├── drive.js           # Google Drive 转写提取和播放器通信
│   ├── shared.js          # 共享工具：设置、字幕合并、提示词生成
│   ├── overlay.css        # 字幕叠加层样式
│   └── page-bridge.js     # 页面级脚本，注入以拦截 YouTube 播放器数据
├── options/
│   ├── options.html       # 设置页面
│   ├── options.css        # 设置页面样式
│   └── options.js         # 设置页面逻辑
└── test/                  # 单元测试
```

node --test
